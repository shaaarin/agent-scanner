# Анализ кода агента через promptfoo — архитектура

Как устроен тип скана «Анализ кода». Что именно сделано при внедрении и
чем реализация отличается от плана — в
[`code-scan-implementation.md`](code-scan-implementation.md).

## Суть

Платформа проверяет агента двумя способами. Динамическое тестирование
собирает агента, запускает его в kind и атакует через DeepTeam. Анализ кода
читает исходники агента сканером `promptfoo code-scans` и находит места,
где возможны prompt injection, утечка персональных данных, лишние
полномочия у модели, опасные инструменты. По каждой проблеме — файл,
строка, серьёзность, рекомендация и готовый промпт для AI-ассистента.

Для пользователя это тип скана «Анализ кода». Агент выбирается тот же, что
и для динамического теста: из его конфигурации берутся репозиторий, ветка
и токен. Всё остальное — как у обычного скана: кнопка запуска, живой
журнал, результаты на странице скана. Агент не собирается и не
запускается, kind и launcher не участвуют.

## Сервисы сканеров

Каждый тип скана выполняет свой сервис:

- `scanner/deepteam` → сервис `scanner-deepteam`, тип `deep_team`;
- `scanner/promptfoo` → сервис `scanner-promptfoo`, тип `code_scan`.

Контракт у всех сканеров один: `GET /health`, `POST /run/{scan_id}` (ответ
сразу, работа в фоновом потоке), фаза, журнал и результат — в control-api
через `PATCH /scans/{id}` и `POST /scans/{id}/logs`.

control-api выбирает сервис по типу скана — словарь `SCANNERS` в
`control-api/app/api/scans.py`, адреса из `SCANNER_DEEPTEAM_URL` и
`SCANNER_PROMPTFOO_URL`. Тип без сканера (`mcp`, `agent_skills`) запустить
нельзя: `start` отвечает 400 и скан остаётся `pending`.

У каждого сканера свой образ: DeepTeam не тянет Node, promptfoo — Python-
зависимости DeepTeam. Общий код не выносится: клиент к control-api у
каждого свой.

## promptfoo code-scans — что важно знать

- Это команда CLI `promptfoo code-scans run`. Образ — Node 24 LTS, версия
  promptfoo зафиксирована (`0.123.1`), пакеты ставятся с
  `--ignore-scripts`, как в официальном GitHub Action promptfoo.
- **Анализ делает облако Promptfoo.** CLI отправляет код на их сервер, а
  серверный агент дочитывает остальные файлы репозитория через локальный
  filesystem-MCP, который CLI поднимает сам. Нужен `PROMPTFOO_API_KEY`;
  модель анализа выбирает Promptfoo, `LLMModel` не участвует.
- **Сканируется только разница между двумя коммитами** — инструмент сделан
  под pull request'ы. Как получаем аудит всей ветки — ниже.
- Файлы больше 500 KB, сборочные каталоги, lock-файлы и бинарники CLI
  пропускает сам.
- С `--json` результат приходит одним JSON в конце работы, до этого CLI
  молчит. Скан длится от нескольких минут до 20+ на больших репо.
- Код возврата 0 — скан прошёл, даже если проблемы найдены. Ненулевой —
  ошибка самого скана.
- **Запуск filesystem-MCP в 0.123.1 небезопасен.** CLI вызывает
  `npx -y @modelcontextprotocol/server-filesystem` внутри сканируемого
  репозитория: пакет каждый раз скачивается из npm, а `.npmrc` репозитория
  может подменить источник. Поэтому сервер ставится в образ заранее с
  фиксированной версией, а `npx` в образе — обёртка (`scanner/promptfoo/bin/npx`),
  которая разрешает только этот вызов и выполняет установленную версию без
  сети.

## Как проходит скан

1. Пользователь создаёт скан типа `code_scan` и нажимает «Запустить».
   control-api переводит его в `running` и вызывает `scanner-promptfoo`.
2. **Инициализация.** Сканер читает скан и конфигурацию агента, проверяет
   параметры и наличие `PROMPTFOO_API_KEY`, пишет в журнал версию
   promptfoo.
3. **Клонирование.** `git clone --depth 1` ветки `git_ref` во временную
   папку. Токен встраивается в адрес так же, как в launcher; в журнал и в
   текст ошибки адрес попадает без токена. Затем — служебные коммиты (ниже)
   и запись в журнал: коммит и число файлов.
4. **Анализ кода.** Запуск promptfoo. Раз в 30 секунд в журнал пишется,
   сколько прошло времени. Если анализ не уложился в `SCAN_CODE_TIMEOUT`
   (по умолчанию 30 минут), процесс останавливается и скан падает.
5. **Сохранение результатов.** Ответ превращается в `Scan.results`, скан —
   `completed`, проставляется `finished_at`. Временная папка удаляется в
   любом случае.

Любая ошибка — неверный токен или ветка, нет ключа, сбой Promptfoo,
таймаут — строка в журнале, статус `failed`, текст в `Scan.error`.

## Как сканируем всю ветку

После клонирования в том же репозитории создаются два служебных коммита
(`git commit-tree`, рабочее дерево не меняется):

- **base** — пустое дерево, без родителей;
- **compare** — дерево проверяемой ветки, родитель — base.

promptfoo запускается с `--base <base> --compare <compare>` и видит каждый
файл ветки как добавленный. Рабочее дерево остаётся на проверяемом коммите,
поэтому filesystem-MCP показывает облаку тот же код.

Проверку изменений ветки относительно `main` не делаем: в платформе нет
понятия pull request, агент описывается одной веткой.

## Данные

Новых таблиц и миграций нет: `scan.type` в базе — строка, добавлено только
значение `code_scan` в `ScanType`.

`Scan.config`:

- `min_severity` — `low` / `medium` / `high` / `critical`, по умолчанию
  `medium`; проблемы ниже порога в отчёт не попадают;
- `guidance` — дополнительные инструкции сканеру, до 4000 символов,
  необязательно.

`Scan.results`:

- `engine`, `engine_version`, `git_ref`, `commit`, `files_in_scope`,
  `min_severity`, `duration_sec`;
- `review` — общий вывод сканера; сюда же идут комментарии без уровня
  серьёзности и причина пропуска скана;
- `summary` — число находок по уровням и `total`;
- `findings` — от критичных к низким: `file`, `line`, `start_line`,
  `severity`, `finding`, `fix`, `ai_agent_prompt`.

Незнакомые поля ответа promptfoo игнорируются, отсутствующие становятся
`null`: формат CLI 0.x может меняться. Результаты DeepTeam остались в
прежнем формате, страница скана различает их по типу.

## Что где в коде

- `scanner/promptfoo/app/runner.py` — фазы, обработка ошибок, защита от
  повторного запуска.
- `scanner/promptfoo/app/repo.py` — клонирование и служебные коммиты.
- `scanner/promptfoo/app/promptfoo.py` — запуск CLI, heartbeat, таймаут,
  разбор ответа в `Scan.results`.
- `scanner/promptfoo/app/main.py`, `control_client.py`, `git_auth.py` — как
  у DeepTeam-сканера; `git_auth.py` — копия из launcher.
- `scanner/promptfoo/bin/npx`, `Dockerfile` — образ и обёртка npx.
- `control-api/app/api/scans.py` — `SCANNERS`, выбор сканера по типу.
- `web/src/api/scanTypes.ts` — подписи типов, фазы по типам, уровни
  серьёзности.
- `web/src/components/CodeScanResults.tsx` — блок результатов.
- `web/src/pages/Scans.tsx`, `ScansDetail.tsx` — форма и страница скана.

## Окружение

`docker-compose.yml`, сервис `scanner-promptfoo`: только default-сеть, без
опубликованного порта. Переменные:

- `PROMPTFOO_API_KEY` — из `.env`;
- `PROMPTFOO_CODE_SCAN_API_HOST` — свой сервер Promptfoo (Enterprise
  On-Prem), пусто — облако;
- `PROMPTFOO_DISABLE_TELEMETRY=1`, `PROMPTFOO_DISABLE_UPDATE=1`;
- `SCAN_CODE_TIMEOUT` — таймаут анализа в секундах, по умолчанию 1800.

У control-api — `SCANNER_DEEPTEAM_URL` и `SCANNER_PROMPTFOO_URL` вместо
прежнего `SCANNER_URL`.

Сервису нужен исходящий доступ к `api.promptfoo.app` и к git-хостингу
агента. Во время скана npm в сеть не ходит.

## Безопасность и ограничения

- Код агента уходит в облако Promptfoo. Для закрытых репозиториев это
  нужно согласовывать.
- Токен репозитория и ключ Promptfoo не попадают в журнал. Хранение токена
  в открытом виде — существующий принятый техдолг.
- Код агента не исполняется, только читается; `npx` в образе не может
  запустить ничего, кроме filesystem-MCP.
- Образ тяжёлый: promptfoo тянет все провайдеры, около 2,3 ГБ на диске.
- На больших репозиториях скан идёт долго, часть файлов promptfoo
  пропускает по размеру. Как сервер Promptfoo ведёт себя на очень большом
  изменении, проверяется живым прогоном.
- Повторный скан того же кода может дать немного другие находки — как и у
  DeepTeam.
- Если сканер перезапустить посреди скана, скан останется в `running` —
  как и у DeepTeam.
- При обновлении promptfoo проверьте, как он запускает filesystem-MCP: в
  исходниках promptfoo уже есть запуск закреплённого пакета без `npx`, тогда
  обёртка станет не нужна.
