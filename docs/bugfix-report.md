# Ревизия кода: найденные и исправленные баги

Прошёл весь код платформы: control-api, оба сканера, launcher, proxy и
web. Ниже — что нашёл, чем это грозило и что исправил. Сначала самое
серьёзное.

## Безопасность

1. **Токен GitLab уходил в облако Promptfoo.** `scanner-promptfoo` клонирует
   репозиторий по адресу с токеном, и git сохраняет этот адрес в
   `.git/config` и в reflog (`.git/logs`). Каталог клона целиком доступен
   облаку Promptfoo через filesystem-MCP, то есть токен мог прочитать
   облачный агент. Теперь после клона `origin` указывает на адрес без
   токена, а reflog удаляется. Проверено: в клоне нет ни одного файла с
   токеном. Файл: `scanner/promptfoo/app/repo.py`.
2. **Ключ LLM агента пересылался в control-api.** Прокси отправлял в
   `/events` заголовок `Authorization` каждого запроса агента, то есть его
   настоящий ключ провайдера. control-api это поле не хранит, но по сети
   ключ уходил. Убрал. Файл: `proxy/addon.py`.
3. **Ветка и адрес репозитория без экранирования в shell-команде сборки.**
   Ветка `main; touch /x` выполнялась бы как команда в поде сборки.
   Теперь значения проходят через `shlex.quote`. Файл: `launcher/app/build.py`.

## Динамическое тестирование (DeepTeam)

4. **Поды агентов не останавливались.** После скана никто не вызывал
   `launcher/stop`, поэтому каждый скан оставлял работающий под агента с
   MITM-сайдкаром. В кластере висел namespace вчерашнего скана. Теперь
   сканер удаляет namespace в конце скана, и успешного, и упавшего. Если
   агент так и не поднялся, namespace остаётся для `kubectl logs`, а в
   ошибке есть подсказка. Файл: `scanner/deepteam/app/runner.py`.
5. **Параллельные сканы одного агента атаковали чужой под.** launcher
   записывает адрес пода в общий `AgentConfig`, а сканер перечитывал его
   оттуда. Второй скан того же агента перезаписывал адрес, и атаки первого
   уходили во второй под. События и результаты при этом перепутывались.
   Теперь `/launch` возвращает адрес (`agent_config_patch`), и сканер
   использует свой. Файлы: `launcher/app/main.py`, `scanner/deepteam/app/runner.py`.
6. **Параллельные сканы смешивали журналы.** Вывод DeepTeam перехватывался
   через `contextlib.redirect_stdout`, а он подменяет stdout всему процессу.
   При двух сканах строки одного попадали в журнал другого, а после
   завершения первого вывод второго мог «потеряться». Теперь вывод
   маршрутизируется по потоку скана. Файл: `scanner/deepteam/app/deepteam_runner.py`.
7. **Атака SyntheticContextInjection из формы роняла скан.** Её
   конструктор требует `target_information`, а сканер создавал атаки без
   аргументов: `TypeError` сразу на старте тестирования. Теперь
   передаётся назначение агента (или описание по умолчанию). Остальные
   21 атака и 21 уязвимость из формы проверены на создание. Файл:
   `scanner/deepteam/app/deepteam_runner.py`.
8. **«Назначение агента» не сохранялось.** Поле есть в форме, но колонки в
   базе не было, в итоговом запросе формы его не было, при редактировании
   оно не загружалось. DeepTeam генерировал атаки без описания цели.
   Добавлены колонка (миграция `0002_agent_purpose`), схемы и форма.
9. **Гонка CA-секрета в launcher.** При одновременном первом запуске двух
   сканов на чистом кластере второй падал с 500: создание общего
   CA-секрета не обрабатывало 409. Файл: `launcher/app/ca_manager.py`.

## Оба сканера

10. **Скан навсегда «Выполняется» после перезапуска сканера.** Если
    контейнер сканера перезапускался посреди скана (пересборка, сбой),
    скан оставался `running`, и запустить его заново было нельзя. Теперь
    сервис при старте переводит такие сканы своего типа в `failed` с
    понятной причиной. У DeepTeam заодно останавливает агента.
11. **Последняя строка журнала терялась.** Сканер сначала ставил статус
    `completed`, а потом писал «Сканирование завершено». Страница скана
    прекращает опрос, как только видит `completed`, и строка могла не
    появиться до перезагрузки. Порядок изменён.
12. **Таймаут анализа кода оставлял процессы.** При таймауте убивался
    только CLI promptfoo, а запущенный им filesystem-MCP оставался в
    контейнере. Теперь останавливается вся группа процессов. Файл:
    `scanner/promptfoo/app/promptfoo.py`.

## Перехват трафика (proxy)

13. **Кириллица в потоковых ответах теряла буквы.** Прокси декодировал
    каждый сетевой кусок отдельно с `errors="ignore"`, и символ UTF-8,
    разрезанный между кусками, выбрасывался: «Привет» сохранялось как
    «Приет». Теперь декодируются только целые SSE-кадры. Файл:
    `proxy/app/openai_provider.py`.

## Интерфейс и control-api

14. **У длинного завершённого скана не было видно конца журнала.** API
    отдаёт журнал по 500 строк, страница брала только первую порцию.
    Теперь дочитывает до конца. Заодно первая загрузка и опрос больше не
    дублируют строки. Файл: `web/src/pages/ScansDetail.tsx`.
15. **Удаление агента со сканами ломало эти сканы.** SQLite не проверяет
    внешние ключи: агент удалялся, а его сканы переставали открываться и
    запускаться. Теперь удаление отклоняется с 409 и понятным текстом.
    Файл: `control-api/app/api/agent_configs.py`.
16. **Ошибки молча глотались.** Неудачное создание или удаление скана,
    запуск со страницы скана и удаление агента писали ошибку только в
    консоль браузера. Теперь она видна на странице. Текст берётся из
    `detail` ответа API, а не сырой JSON. Файлы: `web/src/pages/Scans.tsx`,
    `ScansDetail.tsx`, `AgentConfigs.tsx`, `web/src/api/client.ts`.

## Проверено, не баг

- Время в интерфейсе: API отдаёт даты с `Z`, сдвига часового пояса нет.
- Все 21 уязвимость и 22 атаки из формы есть в deepteam 1.0.9. Кроме
  SyntheticContextInjection (п. 7), все создаются без доп. параметров.

## Не исправлял

- **Токен GitLab в логах init-контейнера сборки** при неудачном клоне —
  известный, задокументированный техдолг launcher.
- **Учётные данные в открытом виде** (ключи моделей, токены, env агента) —
  принятый техдолг MVP.
- **Судья DeepTeam не видит вызовов инструментов агента**, только текст
  ответа — ограничение текущей интеграции, см. MR !3.
- **Провайдер `anthropic` в форме LLM-моделей** на деле работает через
  OpenAI-совместимый клиент: нужен OpenAI-совместимый `base_url`.

## Как проверено

Все сервисы пересобраны, образ прокси запушен в реестр kind, миграция
`0002` применилась к рабочей базе: данные на месте, колонка добавлена.

- **Анализ кода** `testing-repos/langgraph-customer-support` (приватный, с
  токеном): `completed`, 3 high, как и до правок. Последняя строка
  журнала — «Анализ кода завершён». В клоне нет ни одного файла с токеном,
  `origin` без токена.
- **Два DeepTeam-скана одного агента одновременно**: у каждого свой под и
  свой адрес (порты 31814 и 32326), журналы не смешались, в конце каждого
  «Агент остановлен, namespace удалён». SyntheticContextInjection
  создаётся без ошибки.
- **DeepTeam в режиме REST API** (агент 7): адрес из `/launch` с
  сохранённым путём `/runs/wait`, готовность по `/ok`, агент остановлен.
- **Перезапуск сканеров**: искусственные сканы в `running` обоих типов
  после `docker compose restart` стали `failed` с причиной.
- **Назначение агента** сохраняется и читается через API. Удаление агента
  со сканами — 409 с понятным текстом.
- **Гонка CA-секрета**: смоделирована (секрет «не найден», создание — 409),
  `ensure_ca_secret` отрабатывает без ошибки.
- **Экранирование**: ветка `main; touch /x` уходит в команду как одна
  строка в кавычках.
- **Кириллица в SSE**: «Привет, мир» собирается целиком при нарезке потока
  по 1, 2, 3, 7 байт (до правки — «Приет, мир»).
- **Разделение вывода по потокам**: два потока по 50 строк — каждая строка
  в своём журнале.
- **Журнал длиннее 500 строк**: скан 17 (518 строк) дочитывается до
  «Сканирование завершено»; раньше страница показывала 500.
- **Сборка web** с проверкой типов TypeScript прошла.

Не проверено вживую: сама оценка атак DeepTeam (включая генерацию
SyntheticContextInjection). Дневной лимит бесплатной модели OpenRouter
исчерпан, все три DeepTeam-скана упали с `RateLimitError` на генерации
атак — ожидаемо «Ошибка» с понятной причиной. Код вызова агента и судьи
этими правками не менялся.
